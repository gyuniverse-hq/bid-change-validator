### 1. 원문을 보존한 검토 단위

`build_review_inventory()`는 1단계 `build_review_candidates()`를 재사용한다.
키워드로 원문 후보를 제외하지 않고 전달받은 비어 있지 않은 모든 블록을 등록한다.
행 시작의 명시적 조항 기호와 각주 기호에서만 분할한다. CRLF·공백·기호·유니코드와
블록 내부 문자 위치를 그대로 보존한다. 번호 없는 연속 문장을 임의로 쪼개지 않는다.

기존 문서 ID, 원본 파일/추출 텍스트 해시, 페이지·블록·문단 위치를 유지한다.
후보 ID는 원문 스냅샷과 위치 기준이다. 원문 순서 입력이 달라도 같고,
다른 문서를 추가해도 기존 문서의 후보를 재번호화하지 않는다.
버전 간 동일 요건을 연결하는 ID가 아니라 같은 입력의 후보를 추적하는 ID다.

### 2. 상위 조건·각주·참조 힌트

명시적인 제목 위계를 따라 상위 문맥을 보존하고 문서를 넘어서 연결하지 않는다.
블록 위치가 중간에 빠지면 상위 문맥 연결을 끊고 `source_gaps`에 남긴다.
같은 절과 상위 절에 있는 각주는 검토 문맥에 포함한다.

`STRUCTURAL_ANCESTOR`, `ADJACENT`, `PROXIMITY_NOTE`, `CONTEXT_ANCESTOR`는
문서 구조/인접성의 표시다. 각주가 가깝다는 이유로 해당 요건에 적용된다고 확정하지 않는다.
`별표 2`, `붙임3` 등은 `reference_hints`에 보존한다. 실제 별표/다른 문서와의
참조 해결과 의미 검증은 아직 구현하지 않았다. 요청 정책에도 이 한계를 명시한다.

### 3. 요청 분할과 누락 방지

`plan_review_requests()`는 기본 본문 예산 28,000문자, 대상 최대 6개로 요청을 나눈다.
이는 모델 토큰 한도가 아니라 전송 JSON 본문의 문자 예산이다. 토큰 예산과
시스템 프롬프트·출력 여유분 검사는 실제 호출 계층에서 추가해야 한다.

모든 대상은 정확히 하나의 요청 또는 `blocked`에 들어간다.
한 대상의 상위 문맥/각주만으로 예산을 넘어도 일부를 잘라 통과시키지 않는다.
그 대상을 `CONTEXT_EXCEEDS_CHAR_BUDGET`으로 기록하고 필요한 크기를 남긴다.
다른 독립 문서의 처리는 계획할 수 있지만 전체 계획은 `PARTIAL`이다.

- `READY`: 요청 배정 완료 (분석 성공/정답 아님)
- `PARTIAL`: 일부 대상은 요청에 배정했지만 일부는 크기 문제로 미배정
- `BLOCKED`: 요청에 배정 가능한 대상 없음
- `EMPTY`: 처리 대상으로 지정한 후보 없음 (자동 성공 아님)

### 4. 전송 대상과 문맥을 분리

요청에는 `target_candidate_ids`와 `sources`가 따로 있다.
부모·각주를 문맥으로 보냈다고 그 후보의 검토를 완료한 것으로 세지 않는다.
재시도는 원래 inventory에 `target_candidate_ids=missing_ids`를 지정한다.
일부 원문만으로 inventory를 다시 만들어 ID가 바뀌는 문제를 피하고,
누락 후보의 상위 문맥·각주를 유지한 채 재요청을 만들 수 있다.
실제 모델 호출과 재시도 실행은 3단계에서 연결한다.

### 5. 요청 기록

`manifest()`는 원문 텍스트 없이 아래를 남긴다.

- 입력 블록/후보 목록 지문과 공급된 블록 수, 공백 블록 수
- 실제 요청 본문 SHA-256과 문자 수
- 요청별 검토 대상 ID와 문맥에 포함된 ID
- 미배정 대상, 원문 위치 공백, 참조 추가 검토 대상
- 적용한 계획 설정과 계획 전체 지문

원문을 진단 로그에 복사하지 않는다. 모델명·설정·시스템 프롬프트·응답 스키마 지문과
실제 전송/응답 시각은 3단계 호출 경로에서 기록해야 한다.

## 실행 검증

```bash
python -m unittest discover -s apps/api/tests -p 'test_review_*.py' -v
```

별도 실행 환경 Python 3.13.5에서 **70개 통과**:
기존 `test_review_coverage.py` 27개 + 신규 `test_review_plan.py` 43개.
기존 모듈과 테스트는 GitHub blob SHA가 일치하는 내용을 가져와 재실행했다.
SDK 초기화를 피하는 임시 패키지 경로만 사용하고, 검증 대상 모듈은 실제 파일을 로드한다.

신규 검증에는 다음을 포함한다.

- 32,000문자를 넘는 합성 원문을 잘림 없이 복수 요청으로 배정
- 원문 구간 복원, 문서 간 출처 혼합 금지, 제목 위계와 각주 보존
- 문맥만 보내고 처리했다고 세는 오류 방지
- 너무 긴 대상/상위 문맥/각주의 명시적 미배정
- 누락 후보만 같은 ID와 문맥으로 재요청 계획
- 입력 순서/요청 예산을 바꿔도 모든 대상이 배정 또는 미배정 목록에 정확히 1회 존재
- 실제 직렬화 본문과 SHA-256 일치, 원문 없는 진단 기록

전체 API 회귀, 실제 DB·LLM 반복 실행, J14·구내식당 실측, 브라우저 검증은 미실행이다.
이번 코드는 기존 `extract_legacy_slots()`에 아직 연결하지 않았다.
따라서 이번 commit만으로 사용자 화면이나 추출 재현율이 개선됐다고 보고하지 않는다.
