> 이 문서는 이전 제안의 기록이다. 사용자가 “지금 검증해봐야하는거야 발표준비를하는게아니라”로 정정했으므로, 아래 발표 시간표·대본 준비는 현재 작업 지시가 아니다. 현재 작업은 남원 변경 확인 → 실제 재검증 → 원문 대조 → 챗봇 설명·후속 질문의 실행 검증이며, 결과는 33번 보고서에 기록한다.

2026-09-15 사용자 요청: 전체 사용자 평가보다 발표용 데모를 먼저 맞춘다.

## 범위 고정

기본안은 앞서 선정한 남원글로컬 R26BK01684863 000→001 과거 변경 사례, 합성 회사, 3~5분이다. 실제 발표에서 사용할 사례 선택은 사용자 확인에 따라 조정한다. 목적은 실제 공고의 변경과 근거, 현재 결과, AI의 설명·실행 경계를 보여주는 것이다. 참가 가능→불가 반전을 연출하지 않는다.

전체 챗봇의 모든 질문, Core 3개 자유 질의 평가, 장문 설명의 추가 품질·속도 최적화는 발표 준비 뒤로 미룬다. 다만 선택한 동선에서 잘못된 판정·근거·실행 완료를 말하거나 화면이 막히는 문제는 데모 준비 범위에 포함한다. 답변을 하드코딩하거나 검사 실패를 통과로 바꾸지 않는다.

| 1:30~2:15 | 원문 근거와 현재 판정 | 결과를 원문으로 확인한다. 원문 해석이 미확정인 부분은 보류한다. 전체 참가 불가를 업종 변경 하나의 결과로 설명하지 않는다. |

| 3:30~4:00 | 요약 | 변경 발견→근거 대조→영향 확인→다음 행동으로 마무리한다. |

긴 생성이 필요한 시나리오는 사전 실행한 실제 응답을 사용할 수 있지만 반드시 사전 실행 결과라고 밝힌다. 녹화·준비된 결과를 즉석 생성처럼 설명하지 않는다.

## 현재 확인한 것

현재 코드 a6de96f의 로컬 실제 브라우저에서 eval-j13으로 로그인하여 변경 이력·근거 원문·참가자격 화면을 읽었다. 로그인 외 쓰기는 차단했고 모델 호출은 하지 않았다. JS 오류·차단된 쓰기 요청은 0이었다.

근거: Git 제외 `.ci-results/user-evaluation/demo-readiness-2026-09-15T04-07-34-760Z/readiness.json`과 화면 캡처 3개.

- J13의 저장 판정은 충족 3건·확인 필요 0건·미달 2건이며 기존 현장 방문 답변을 유지한다.
- 원문 PDF/HWP/HWPX와 현재 판정 화면이 열린다.
- 변경 이력은 현재 **재검증 제안 버튼까지만** 보인다. 결과 비교 영역은 프런트엔드의 실행 결과 상태가 있어야 표시된다. 새로고침에 견디는 발표 동선과 실행 결과 확인이 추가로 필요하다.
- 따라서 **발표 데모 준비 완료로 보고하지 않는다.** 이번 읽기 검사는 실제 재검증 실행 성공 검사도 아니다.

## 남은 일을 세 묶음으로 제한

1. **발표 전용 사례:** 기존 J13 답변·판정을 건드리지 않는 별도 로컬 사례를 준비하고 기준/현재·회사·요건·원문 출처를 고정한다. 원본 공용 DB를 변경하지 않는다.
2. **선택한 동선 연결:** 변경 비교→재검증 결과→원문→AI 설명이 이어지고, 새로고침 시 어디서 다시 시작할지 명확하게 한다. 이 동선에서 노출되는 내부 검증 지침과 과거 공고 혼동만 우선 수정한다.
3. **전체 리허설 한 번:** 같은 계정·시나리오로 실행 결과, 클릭 순서, 응답 시간, 새로고침 복귀를 확인하고 발표 대본·문제 발생 시 보여줄 실제 기록을 확정한다. 리허설에서 실패한 부분만 보완한다.

이 세 묶음을 마친 뒤에 사용자에게 발표 연습을 요청한다. 개별 자유 질문을 계속 추가하는 방식으로 완료 범위를 늘리지 않는다. merge·배포 및 제품 전체 완료 판단은 별도다.
