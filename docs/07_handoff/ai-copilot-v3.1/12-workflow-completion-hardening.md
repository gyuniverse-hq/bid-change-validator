## 수정한 원인과 동작

1. **제안의 근거 누락:** 실제 ActionProposal은 생성됐지만 PROPOSE_ACTION의 완료 기준은 fact_ids가 비어 있었다. 서버가 생성한 제안의 대상·입력값·저장 전 상태를 절차 근거로 제공한다. 확인 전 저장·자격 검증 완료를 주장할 수 없다. 특정 요건에 전달한 입력 제안에는 다른 요건의 질문을 완료 조건으로 끼워 넣지 않는다.
2. **짧은 동의의 오분류:** 같은 기준의 직전 메시지에 실제 제안이 있을 때 “응/네/좋아요”는 서버 작성 안내로 처리한다. 문서 조회나 쓰기를 실행하지 않으며 앞선 제안 카드의 명시 확인을 안내한다. 모델이 임의로 ACKNOWLEDGE_ACTION을 계획할 수 없고, 다른 공고·회사·판정 기준의 과거 제안을 재사용하지 않는다.
3. **가정 처리 누락:** 모델에 문서 조회 허용 여부를 전달한다. 명시적 가정 문구가 일반 판정 조회로 축소돼도 가정 fact가 남도록 서버가 REVIEW_ASSUMPTION을 보존한다. 선택 항목의 후속 질문에서도 새 가정을 버리지 않는다. 조건부 결론과 실제 보유·저장 판정·전체 자격을 구분한다. 문서 조회가 불가한 요청을 조회 완료로 강제 승격하지 않는다.
4. **문장별 근거와 완료 항목의 관계:** 가정·조건·한계를 여러 검증된 문장으로 설명할 때, 각 문장이 모두 같은 가정 fact를 인용해야만 완료되는 오류를 수정했다. 모든 문장은 SUPPORTED여야 하고, 문장들의 근거 집합에 해당 완료 항목의 실제 근거가 반드시 포함돼야 한다. 근거 없는 안내나 거절된 문장은 여전히 완료를 만들 수 없다.
5. **화면과 출처:** 절차 근거는 새 PROCEDURE 출처로 전달하고 “작업 안내”로 표시한다. 서버 제안이나 동의 안내를 “저장된 데이터”로 표시하지 않는다. UUID·내부 필드를 본문에 나열하지 않도록 생성 지침도 보완했다.

관련 제품 코드: acceptance.py, orchestration.py, answer_validation.py, v31_contracts.py 및 웹 envelope-answer.tsx/copilot-v31.ts. 판정 엔진의 자격 기준이나 장비 예외 로직은 변경하지 않았다.
