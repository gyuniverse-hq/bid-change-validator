2026-09-15. 시작 HEAD `ee207ef`. 단계: ④ 통합 검증 보완. 실제 모델 재검증 실행 완료, 전체 job 미통과.

## 변경

실제 모델의 fact citation 생성 경로에서 READ_DOCUMENT 작업이 있으면 각 주장에 선택적 submission 구조를 받는다. 서류, 제출 단계, 필수/협조/조건부/확인 필요, 기한, 방법, 예정일 상태, 예외·확인할 일을 포함한다. 같은 서류가 입찰과 계약 단계에 등장하면 별도 주장으로 작성하도록 한다. 추가 모델 호출은 없다.

서버는 구조의 모든 필드를 표시 문장으로 변환한 다음 기존 근거·화행·의미·완료 기준 검증에 전달한다. 구조를 받았다는 이유로 검증 통과나 회사의 자격 충족으로 승격하지 않는다. 생성 문장의 별도 text는 submission이 있을 때 사용하지 않아 검증하지 않은 중복 설명이 추가되지 않는다. 자료 읽기 이외 요청과 보완 생성은 기존 경로를 유지한다.

이는 검증 전 초안의 구조화이다. 영구 저장된 의무 원장, 모든 서류의 완전한 추출, 제출 단계 충돌의 자동 해결까지 구현됐다는 의미는 아니다. 생성 모델이 구조를 실제로 잘 활용하는지와 동일 서류의 복수 단계 의무를 정확히 답하는지는 실제 모델 확인이 필요하다.

## 이어서 할 일

### 재시도 후 환경 복구

사용자 재시도 승인 후 자동 검토를 통과했다. Docker 실제 실패 원인은 Windows의 기존 임시 소켓 재접근 오류였다. `Docker/run`의 0바이트 소켓 4개와 `docker-secrets-engine`의 0바이트 소켓 하나를 확인했다. Docker 프로세스를 종료하고 두 폴더를 각각 타임스탬프가 있는 preserved 이름으로 보존한 뒤 재시작하여 엔진 29.7.2 응답을 확인했다. DB/볼륨/설정을 삭제·초기화하지 않았다.

평가 컨테이너 ID, DB명, PostgreSQL 버전은 이전과 동일했지만 동적 로컬 포트가 54560에서 59075로 바뀌었다. 기존 manifest를 백업하고 포트만 갱신했다. 원래 보존 검사 자료는 수정하지 않고 포트 갱신 사본으로 검사하여 원래 J13 사례·프로필·분석·답변·판정 해시 일치가 통과했다.

평가 API v28과 웹 5181을 시작했다. 첫 브라우저 시도(`chat-1789465762973`)는 웹 준비 전 CONNECTION_REFUSED이며 모델 호출 없이 실패했다. 준비 완료 로그 확인 후 세 턴 검증을 재실행했다.

### 사용자 재승인 후 시도

사용자가 재승인한 뒤 보존 확인 명령은 실행됐으나 Docker의 `dockerDesktopLinuxEngine` 파이프가 없어 연결에 실패했다. 이때 DB 보존 확인은 완료되지 않았다. Docker 프로세스가 없음을 확인하고 사용자 설치 경로의 Docker Desktop을 Hidden으로 시작했다. 시작 명령은 성공했지만 엔진 준비 완료를 의미하지 않는다.

후속 Docker 준비 상태 및 웹 프록시 설정 조회 명령은 자동 승인 검토에서 다시 거절됐다: `Error running remote compact task: Selected model is at capacity.` 해당 조회는 실행되지 않았다. 우회하지 않았으며, 평가 API/웹 시작과 실제 모델 호출은 하지 않았다. 다음 재개 때 Docker가 이미 시작 중이거나 준비됐을 수 있으므로 중복 시작 전에 상태부터 확인한다. 추가 모델 비용은 이번 재개 시도에서 발생하지 않았다.

환경 복구·보존 확인·서버 실행·세 턴 검증은 완료했다. 다음은 서로 다른 서류/단계의 병합을 검증 전에 구분하고 준비 순서를 각 제출기한에 연결하는 보완이다. 중복·응답 시간도 재검사한다. 실제 모델 실패를 해결한 뒤 ⑤ 사용자 재평가 → ⑥ 최종 통합 판단으로 진행한다.
