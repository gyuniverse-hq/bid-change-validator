## 이번에 발견·수정한 것

공유된 화면 원문 내보내기의 참가자격 절에서 `1)「...`, `2)「...`, `○ ...`가 경계로
인식되지 않아 업종·지역 등의 조건이 앞 NOTE 후보에 붙는 것을 재현했다.
같은 발췌를 한 블록으로 재생하면 검토 단위가 5에서 13으로 분리되며 원문/offset은 그대로 보존된다.
13은 제목·각주도 포함한 검토 단위이며 자격요건 건수/재현율이 아니다. 실제 PDF/DB 대조는 아직 없다.

- 새로운 계획은 v2로 구분하고 이전 v1의 ID·분리 규칙을 변경하지 않음.
- 저장 그래프는 저장 당시 계획 버전으로 읽음. 기존 고정 v1 snapshot 읽기 회귀 추가.
- 서로 다른 분리 계획의 결과 비교는 CANDIDATE_PLAN_CHANGED/REVIEW_REQUIRED로 처리.
- 기존 반복 측정기에 document_graph_v1을 추가: 제품 그래프→JSON 왕복→회사 판정→동일 차수/변경 차수 비교.
- 원문·회사 상세를 공개 테스트/측정 보고서에 복제하지 않음. 합성 형식 회귀와 원문 발췌 재생을 구분.

- 회사와 독립된 공고 원문 분석/그래프를 저장하고 회사만 바꿔 판정할 때 모델을 재호출하지 않음.

- `/qualification-graph?caseId=...`의 별도 화면과 API. 기존 현재 판정/Copilot 결과로 자동 승격하지 않음.
