## 6-B에서 연결한 것

- 상세 화면도 5단계 `qualification-state`가 선택한 분석/판정 ID로 읽는다.
- 회사·공고·차수·규칙·기준일·요건/근거 연결을 검사하고 조회 전후 상태를 재확인한다.
- 목록과 상세는 같은 `presentQualificationState`로 상태를 표시한다. 서로 다른 Case의 결과까지 같다고 가정하지 않는다.
- 재판정/조회 실패를 미검토·0건으로 바꾸지 않고, 과거 판정은 현재 판정과 분리한다.
- 분석과 회사 판정 실행을 분리한다. 현재 분석으로 회사 재판정은 LLM 재추출을 하지 않는다.
- POST 응답을 그대로 화면 결과로 사용하지 않고 상태/근거를 다시 조회한다.
- 저장 확인 후 GET 실패는 `REFRESH_FAILED`, 결과를 확인 못한 POST는 `WRITE_UNCONFIRMED`다. 자동 쓰기 재시도는 없다.
- 기준 차수 검토 준비를 별도 버튼으로 제공하고, 기준 차수의 실패가 현재 판정을 덮지 않게 한다.
- 판정 표는 현재 회사 입력을 과거 대조값으로 대신 쓰지 않고 저장된 `profile_refs`를 사용한다.
- Copilot의 확인 버튼/잠금은 기존 컴포넌트를 사용한다. 완료/조회 실패/결과 불명 상태 변화와 창 복귀 시 읽기를 갱신한다.

## 이번 검증

Node 22.16.0에서 `tests/qualification-detail.test.cjs` **85개 통과**.
실제 새 TS 모듈과 기존 API/state 모듈을 실행했고 최하단 HTTP 또는 읽기/쓰기 포트만 대역이다.
기존 api.ts, qualification-api.ts, qualification-state.ts, qualification-state-api.ts는 부모 Git blob SHA와 일치 확인 후 사용했다.
새 데이터 모듈 3개는 실제 기존 API 타입과 함께 strict tsc 검사 통과. 새 TSX 3개는 구문 검사만 통과했다.

React/vinext 등 전체 의존성이 없는 실행 환경이며 npm 저장소 조회가 EAI_AGAIN으로 실패했다.
따라서 pnpm build, 전체 프로젝트 tsc, 실제 React 렌더·브라우저·시각 검수는 **미실행**이다.
백엔드 코드/DB/실제 모델을 이번에 실행한 것이 아니다. 85개를 추출 성능 개선 수치로 사용하지 않는다.
