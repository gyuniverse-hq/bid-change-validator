## 무엇을 바꿨는가

`change_impact.py`는 현재 판정에 연결된 재검증 기록을 읽는다. 사례·회사·공고 차수·양쪽 분석·양쪽 판정·규칙 버전·기준일·회사정보 snapshot이 일치하는지 검사한다. 요건별 기준/현재 상태와 재검증 여부, 종합 판정, 회사정보 동일 여부를 함께 제공한다. 재판정을 실행하거나 판정을 새로 계산하지 않는다. 회사정보는 판정 당시 저장값이며 현재 실제 등록증 확인과 구분한다.

기록 부재·다른 회사정보·오래된 분석·다른 기준일 등은 구체적 이유와 함께 비교 불가로 처리한다. 읽은 비교 근거는 fingerprint로 고정하고 답변 직전 다시 확인한다. 이 경로는 Namwon 공고번호나 1224/1227 정답을 하드코딩하지 않는다. 다른 공고도 연결된 재검증 기록이 있어야 이용할 수 있으며 이번에 Core 전체 실검증을 수행한 것은 아니다.

변경 영향 완료 기준은 전후 종합 판정, 개별 요건 변화, 같은 비교 기준, 기존 미달을 요구한다. 실제 증빙 확보나 새 판정 실행을 완료 조건으로 더하지 않는다. 저장 분석 발췌 차이를 공고 원문 전체의 조항 삭제/추가로 단정하지 않도록 생성·검증 기준을 맞췄다. 업종군 결합 관계가 `UNRESOLVED`이면 그 사실을 근거에 포함하고 AND/OR 확정을 거부한다. Q-009 해석을 확정하거나 보류를 해제한 것이 아니다.

완료된 job에 새 후속 질문이 들어오면 모델의 `resume_unresolved` 표시로 과거 완료 요청을 덮어쓰지 않는다. 미완료 job을 잇더라도 새로 요청한 READ 종류를 삭제하지 않고, 추가 요청을 완료 기준에 남긴다. 기존 요청과 실행 영수증은 유지한다.
