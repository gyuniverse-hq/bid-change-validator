## Q-007 — 장문 전체 검토는 아직 완료되지 않음

**근거:** 전체 범위 검색은 최초 74/74 record를 반환했다. 실제 모델 생성용 근거 예산에서는 73개가 제외됐고 검증 입력도 한도를 넘었다. 손상된 HWP/동일 표준문서를 제외한 최종 실행은 60/60 record를 읽었지만 여전히 PARTIAL이었다. 핵심 8개 검색어가 fallback에 보였다는 것은 완성된 요약·예외 이해의 증거가 아니다.

**대안 A:** 지금의 명시적인 부분 응답을 유지하고 point 질문만 평가한다. 안전하지만 사용자의 전체 문서 이해 목표를 충족하지 못한다.

**대안 B:** 전체 문서를 섹션·조건·예외 ledger로 나눠 읽고, 각각의 처리 상태·원문 위치·검증 결과를 추적한다. 모델 호출은 작업 단위 예산 안에서 분할하고, 표시할 요약만 별도로 줄인다. 손상 문서는 재추출하거나 같은 원본의 검증된 대체 문서임을 확인해야 한다.

**권장:** A의 거짓 완료 방지는 유지하되 B를 다음 구현 범위로 확정한다. 원문 수를 줄여 PASS를 만들거나 상한만 높여 해결됐다고 하지 않는다. 이 항목은 기존 Q-007의 실제 모델 반례로 갱신한다.

## Q-008 — 분석 표현·예외 계약과 제품 판정이 맞지 않음

**근거:** J13의 `1227` 보유가 `업종명(1227)`과 일치하지 않았고, J15/J16의 예외 입력은 Golden scenario_facts에만 있으며 현재 판정에 반영되지 않았다. 최신 v2 분석은 원문 운반 예외를 누락했다. 이 문제는 챗봇의 말투나 완료 판정 변경으로 해결할 수 없다.

**대안 A:** 알려진 문구에서 1227만 뽑거나 예외 확인 bool을 강제로 SATISFIED에 연결한다. 코드/명칭의 모순, 법적 허가·장비 미확인을 놓칠 수 있어 비권장이다.

**대안 B:** 정규화된 업종 코드와 표시 이름을 분리하고, `운반업 등록 OR 해당 폐기물의 직접 운반 허가·장비 조건`을 출처가 고정된 복합 요건으로 표현한다. 처분업 대안·현장 방문 등 필수조건도 판정/수동 확인 대상에서 잃지 않게 한다. 사용자 답변의 대상·근거·적용 차수를 명시하고, 미입력은 UNKNOWN으로 둔다. 단순 트럭 보유를 법적 예외 충족으로 해석하지 않는다.

**권장:** B의 계약과 Golden 기대값을 원문 기준으로 검수한 뒤 구현한다. 판정 의미가 바뀌면 규칙 버전과 기존 결과의 재판정 경계를 함께 변경해야 한다. 기존 composite/role 방어를 전역 해제하거나 현재 snapshot/정답을 덮어쓰지 않는다. 원래 Q-005의 J15/J16 문제와 함께 설계 대화에 전달한다.

## 사용자 평가 진입 조건

1. Q-008 정규화·복합 예외·미확인 상태와 Golden 기대값을 검수·반영하고, 동일 snapshot으로 J13~J16을 다시 실행한다.
2. Q-007 장문 ledger와 손상 원문 처리 후 실제 전체 조건 질문이 의미 검증을 마치도록 한다. PARTIAL로 남는 조건은 항목별로 명시한다.
3. 이 두 변경의 단위·DB·모델·브라우저 회귀를 확인한 뒤 17번 평가표로 사람 평가를 시작한다.

자동 승인 검토에서 처음에는 snapshot 로컬 복사, 다음에는 OpenAI 전송이 보류되었다. 각각 사용자가 범위와 목적지를 승인한 뒤 재실행했다. 현재 그 두 승인 차단은 해소되었으며, 남은 보류는 위 제품 품질 실패다.
