## Q-022 — 검수 근거 식별값까지 구조화 값 변경으로 집계함

**근거:** 실제 J13/J14 변경 이력 화면이 운반 업종코드 외 처분·재활용업군도 구조화 변경으로 표시했다. 해당 업종군의 원문·코드·관계는 같고, 차수별 검수 `source_fingerprint`만 달랐다. 저장된 재검증은 총 4건을 처리했지만 실제 구조화 조건 변경은 1건이다.

API v34의 `N2-1789517221239`, `N3-1789517221227`은 제출처 문제의 다른 표현을 드러냈다. 모델이 차량 근거를 인용하지 않고 계획서 근거만 선택하거나, “감독원에게 제출하고 … 승인”처럼 뒤에 말을 붙이면 앞선 보호 조건에 해당하지 않았다. 두 Job은 FAIL로 보존했다. `N1-1789517452531`도 마지막에 미완료였으며 다음 대표 Job들은 pause 표식으로 시작을 보류했다.

**근거·보완:**

- 제출처가 명시된 인용에서 묶음의 모든 서류가 확인되지 않으면 동일 제출처를 일괄 적용하지 않는다. 확인된 원문 문장과 나머지 제출처 확인 필요를 구분하며, 뒤따르는 승인 표현이 제출처 근거를 대신하지 않는다. 특정 공고의 서류·기관명을 정답으로 넣지 않았다.
- “날짜가 있는 방문 기간 + 방문 후 제출”처럼 사건 기준과 날짜가 함께 있는 필드는 사건의 실제 발생을 추정하지 않도록 `시점 미확정`으로 보수적으로 표시한다. 날짜와 사건 문구 자체는 보존하고 원문 대조를 계속 받는다. 구체적 날짜가 없더라도 명시된 기준 사건이 있으면 이를 버리지 않는다.
- 여러 직접 확인 항목을 묶은 준비 순서는 회사가 모두 충족한다는 단정이나 하나의 답변 입력과 다르다. 모든 항목이 읽기·직접 확인 대상이고 명시적으로 순서를 제안한 경우에만 혼합 항목 기계 차단을 적용하지 않고 기존 의미 검증으로 넘긴다. 입력 가능한 항목을 섞거나 회사 충족을 단정하는 경우는 계속 차단한다.

이는 검증 결과를 PASS로 바꾸는 처리가 아니다. 후보의 근거와 시간·화행을 일관되게 표현한 후 같은 의미·원문·완료 검사를 받는다. 합성 반례 및 기존 공통 회귀 `copilot-v31-20260916T001450Z` **557 passed**, 고유 백엔드 **1039 passed / 11 skipped**. API v35의 실제 출력으로 새 근거를 확인한다.
