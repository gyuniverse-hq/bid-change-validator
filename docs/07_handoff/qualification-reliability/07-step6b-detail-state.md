# 6-B — 상세 화면의 현재 상태·판정·근거 연결

부모 commit: `1e1f5b2a56e415c420cb9f83e52b98a555d644a1`.
작업 브랜치: `refactor/qualification-reliability`.
이 문서는 코드 연결과 분리된 TypeScript 검증 결과다. 배포·브라우저·실제 모델 성능 검증 기록이 아니다.

## 1. 읽기 경로

```text
Case 조회
→ 공고 차수 + qualification-state
→ state.analysis_run_id로 분석 조회
→ state.selected_judgment_run_id로 판정 조회 (없으면 과거 결과로 fallback하지 않음)
→ 같은 판정 ID로 추가 질문 조회
→ 기준 차수의 과거 분석·판정은 별도 조회
→ state와 Case 기준 재조회
→ 동일 기준일 때만 전체 상세를 한 번에 반영
```

상세는 최신 판정 목록에서 독자적으로 현재 결과를 선택하지 않는다.
분석/판정/회사/공고 차수/규칙/기준일, 중복 요건, 참조 근거, 문서의 차수 범위를 검사한다.
상태 지문이 같아도 실제 상태 필드가 달라지면 혼합된 응답을 거부한다.
JSON 객체의 속성 나열 순서만 바뀐 것은 기준 변경으로 보지 않는다.

실제 Backend 분석 상세에는 summary의 requirement_count/evidence_count가 없다.
새 소비 코드는 상세의 배열 길이를 사용한다. 해당 개수 필드가 추가로 오면 배열과 일치하는지 검사한다.
기존 API 타입 선언을 이 작업에서 전역 변경하지 않았다.

기준 차수의 조회/연결 오류는 경고와 재검증 비활성으로 처리한다. 현재 판정을 과거 판정으로 대체하지 않는다.
기준/현재 차수가 동일한 기존 Case는 변경 비교 대상으로 만들지 않는다.
추가 질문 조회 실패도 판정 실패로 만들지 않고 경고와 읽기 재시도 동작을 남긴다.

## 2. 명시적인 쓰기 동작

- **현재 분석으로 회사 재판정**: 새 상태를 확인하고 같은 분석으로 판정한다. 공고 추출을 재호출하지 않는다.
- **현재 차수 다시 분석**: 현재 차수의 실제 분석 API를 호출한 뒤 판정한다.
- **분석하고 판정**: 사용할 수 있는 기존 분석이 있으면 재사용하고, 없으면 분석한다.
- **기준 차수 검토 준비**: 기준 차수의 분석/판정을 별도로 준비한다. 현재 차수 표시를 덮지 않는다.
- **전체 변경 요건 재검증 제안**: 기존 Copilot 제안/확인 버튼 경로를 유지한다.

회사/Case/차수 변경 또는 재판정 대상 분석 변경은 쓰기 전 확인에서 중단한다.
이 확인은 서버 쓰기 경계의 권한·최신성 검사나 낙관적 잠금/CAS를 대체하지 않는다.
분석이 FAILED/0건이면 후속 판정을 호출하지 않고 상태를 읽는다.
화면을 떠나면 아직 전송하지 않은 후속 요청을 중단한다. 이미 전송된 POST를 취소했다고 주장하지 않는다.

쓰기 응답은 곧바로 최종 화면 결과가 되지 않는다. 상태와 근거를 다시 읽어 선택 기준을 확인한다.

| 결과 | 처리 |
|---|---|
| 정상 저장·후속 조회 성공 | 서버가 선택한 결과와 기준을 표시 |
| 저장됐지만 다른 결과가 현재 선택됨 | 저장 사실과 현재 결과가 다름을 알리고 현재 상태 표시 |
| 저장 응답 확인 후 GET 실패 | REFRESH_FAILED, 확인된 저장 ID 보존, 상태만 재조회 |
| POST 오류/불명확한 응답 | WRITE_UNCONFIRMED, 자동 POST 재시도 없이 현재 상태만 조회 |
| 화면 이동/요청 세대 변경 | ABANDONED 또는 오래된 응답 무시 |

한 번 성공한 후보 응답을 다시 저장하거나 유리한 판정이 나올 때까지 반복하는 흐름은 없다.
상태만 재조회하는 버튼은 어떤 분석/판정 생성 API도 호출하지 않는다.

## 3. 표시와 원문

- 목록과 같은 presentQualificationState를 사용한다. AVAILABLE과 분석 완전성은 별개다.
- 선택 판정이 없으면 충족/미달/확인 건수는 0이 아니라 `—`다.
- 원문 전체를 빠짐없이 분석했다고 단정하지 않는다. COMPLETE도 처리 기록의 의미로 표시한다.
- 과거 저장 결과와 저장 기준일을 명시하고, 오래된 결과를 현재 판정으로 세지 않는다.
- 요건 표의 값은 해당 판정에 저장된 profile_refs를 사용한다. 현재 프로필의 합계/인원으로 대체하지 않는다.
- USER_ANSWER는 저장 답변 기준임을 알리며 최신성 미확인을 숨기지 않는다.
- 근거 보기는 선택된 분석에서 확인된 Evidence를 인라인 표시한다. 새 조회 시작 시 선택을 초기화한다.
- 판정 밖 기록 0건은 발견하지 못한 요건까지 없다는 뜻이 아님을 표시한다.
- 제목/회사명/검토 이동 목록의 보조 조회 실패는 현재 판정 조회 실패와 분리한다.

기존 화면의 공고 요약/탭/요건표/원문/판정 밖 기록/변경 재검증 기능을 별도 컴포넌트로 이동했다.
일반 경로의 목록은 6-A 카탈로그 그대로다. caseId 없는 시작 화면은 기존 선택 목록을 유지하며
그 범위 밖의 공고는 공고 검색 링크로 안내한다. 기존 검토 건 재사용은 6-A openReviewTarget을 사용한다.

## 5. 실제 실행 검증

```bash
cd apps/web
node --test tests/qualification-detail.test.cjs
```

Node 22.16.0, TypeScript 5.8.3 (프로젝트 지정 5.9.3의 전체 빌드는 미검증): 85개 통과. 같은 테스트의 재실행을 합산하지 않았다.
실제 새 core/view/API 어댑터와 기존 api.ts/qualification-api.ts/state.ts/state-api.ts를 실행한다.
테스트는 합성 API 자료이고 HTTP 또는 읽기/쓰기 포트가 대역이다. React 렌더·HTTP 서버 E2E는 아니다.
기존 네 모듈은 부모 Git blob SHA와 일치하는 원문으로 검증했다.

새 데이터 모듈 3개 + 실제 기존 API 타입: strict/noEmit/ES2022/DOM 타입 검사 통과.
새 TSX 3개: TypeScript 파서 구문 검사 통과. React 타입 검사나 브라우저 검증으로 표현하지 않는다.
검증 환경의 npm 저장소 연결이 EAI_AGAIN으로 실패해 pnpm/전체 의존성 설치와 전체 build를 실행하지 못했다.
의존성 파일이나 lockfile을 임의 수정해 우회하지 않았다.

주요 반례: 회사/차수/규칙/근거 불일치, 실패한 최신 분석, 현재 미선택 과거 판정,
조회 도중 기준 변경, 질문/기준 차수 조회 실패, 단일 차수 중복 비교, 재판정 시 재추출 금지,
저장 후 조회 실패·불확실한 POST의 자동 재전송 금지, 이동 중 후속 쓰기 중단, 상태 기반 건수/경고.

## 6. 남은 검증 및 연결

전체 프로젝트 tsc/pnpm build/실제 React 렌더/브라우저·시각 검수는 미실행이다.
운영 PostgreSQL/전체 API 회귀/실제 LLM/J14·구내식당 반복/변경공고/Copilot E2E도 미실행이다.
새 의미 그래프 추출은 아직 내부 명시적 경로이며 기본 제품 추출을 교체하지 않았다.
전체 공고 조항 간 적용·예외·저장 계약을 검증한 뒤 전환해야 한다.
이번 6-B 코드는 기존 저장 분석의 상태 표시를 개선하며, 이것만으로 추출 성능이 개선됐다고 주장하지 않는다.
