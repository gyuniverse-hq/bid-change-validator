## 이번 연결

- 공고 원문 분석은 회사와 독립. 회사가 달라져도 같은 저장 그래프로 판정하며 LLM은 다시 호출하지 않음.
- 원문/조항/그래프/관계/미해결 정보를 버전 있는 스냅샷으로 저장, 조회 시 내용과 근거를 재검증.
- 전용 `qualification_graph_runs`, `qualification_graph_judgment_runs` 테이블, migration023 추가.
- 명시한 두 실행을 GET으로 비교. 원문 동일·추출만 변화는 분석 불일치이지 요건 삭제가 아님.
- 문서/조항 대응이 애매하면 검토 필요. 순서 기반 요건 키나 값만을 동일성으로 사용하지 않음.
- `/qualification-graph?caseId=...` 화면에 이전/현재 원문·구조화 의미·관계 차이를 표시.
- 기존 기본 분석·현재 판정·Copilot 결과를 새 그래프로 자동 교체하지 않음.

## 실행 조건과 한계

검증 환경에서 `023_qualification_graphs` 마이그레이션과 `QUALIFICATION_GRAPH_ENABLED=true`가 필요하다.
기본값은 false이고 배포/팀 공용 DB에 적용하지 않았다. CI의 일회용 PostgreSQL에서만 적용했다.
기존 슬롯형 `review_v1`과 새 graph 경로의 저장·판정은 별개이며 같은 성능 수치로 합치지 않는다.

관계 원문 검사/저장 왕복은 해석의 정답 보증이 아니다. 여러 문서의 적용 관계, 미해결 문맥,
장비·허가 사실, 재량 예외의 실제 인정은 남아 있다. 비교의 자동 조항 대응도 휴리스틱이다.
실제 남원글로컬 원문·차수·회사·기준일·모델을 고정한 실행은 아직 수행하지 못했다.
따라서 7단계 전체 완료, 실제 추출 정확도 개선, 데모 성능 확보로 표시하지 않는다.

Copilot 소스·골든셋·평가기·기존 판정 규칙·lockfile은 변경하지 않았다. develop/main 미병합.
