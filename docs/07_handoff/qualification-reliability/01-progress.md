## 이번 구현

- GET `/api/v1/qualification-notice-catalog`: 회사 권한 검사 후 동일 검색 범위의 현재
  공고/저장 상태를 일괄 읽고 상태 필터 후 페이지 분할. 원문/회사 상세/모델 호출/쓰기 없음.
- 5단계 상태 선택 함수를 재사용. 조회 실패/자료 불일치를 미검토로 합치지 않음.
- 사업 유형은 q 범위, 상태 집계는 q+사업 유형 범위. 목록 상위 100건에 갇히지 않음.
- 공고 화면의 검색/회사/유형/상태/페이지를 서버 카탈로그에 연결.
- 회사 기준 미리 비교는 미저장 계산임을 표시하고 목록과 선택 회사를 맞춤.
- 검토 열기에서 실제 차수/회사 재확인, 공고별 기존 Case 페이지 탐색 후 재사용.
- 상세 화면과 Copilot 정책은 이번에 수정하지 않음. 새 모델 추출 기본값도 켜지 않음.

## 검증

99개 통과: 새 서비스 SQL/HTTP/상태 선택 50개, 실제 TS 모듈의 표시/계약/요청 49개.
SQLite 최소 ORM·인증/프로필 로더 대역이며 모델/HTTP 네트워크 대역을 사용했다.
기존 `state_contract.py`/`state_service.py`는 부모 Git blob SHA 일치 확인 후 실제 로드했다.
순수 TS 상태 계약 strict 검사 및 TSX 구문 검사는 통과. 전체 프론트 빌드/타입/브라우저는 미실행.

운영 PostgreSQL/마이그레이션/전체 앱·API 회귀/실제 LLM/J14·구내식당/변경공고/Copilot/CI는
이번 실행 범위 밖이다. 근본 추출 정확도가 향상됐다는 실측을 아직 확보하지 않았다.

## 보존한 경계

- develop/main 미병합. PR #136 미병합. 골든셋/평가기/기존 판정 규칙/DB 스키마 유지.
