# 제출 서류·마감일 질문 재검증

2026-09-15. 현재 단계: ⑤ 사용자 평가에서 발견한 ④ 통합 검증 결함 보완.

**후속 재점검:** [28 — 노션 과업 기준 대비 구현·검증 차이표](28-job-design-gap-audit.md)에서 현재 단계를 **④ 과업 단위 통합 검증 재정비**로 정정했다. 아래 실행 결과는 당시 이력으로 보존한다. Q-011은 독립 질문 전용 기능의 추가가 아니라 공통 통합 답변 작업의 서류·기한 사례로 다룬다. 정식 사용자 평가 진입 및 전체 과업 완료를 의미하지 않는다.

## 사용자 실패와 확인된 원인

질문: “이 공고에서 제출해야 하는 서류와 마감일을 알려줘.” 사용자 응답은 원문에 제출기간이 있는데도 확인 불가라고 안내했다. 최초 실행의 내부 trace는 확보하지 못했으므로 당시 경로를 추정으로 확정하지 않는다.

코드와 신규 실행에서 다음을 확인했다.

- 7,000바이트 근거 예산을 넘는 원문 fact/source 그룹은 통째로 제외됐다. 장문 분할 검토는 특정 전체 원문 표현에만 연결되어 있었다. 긴 원문 끝의 제출 마감이 제외되는 회귀검사를 추가했다.
- 의미 계획 모델이 같은 질문을 저장 판정 조회로 분류하기도 했다. 공고의 서류·마감일을 명시한 단독 요청은 문서 조회로 고정했다. 회사 판정·저장·비교 등 복합 요청은 이 규칙에서 제외한다. 문서 사용 동의 경계는 유지한다.
- 원문 검색은 한국어 표현 차이로 일반 안내만 고를 수 있었다. 여러 절에 걸친 서류·기한 요청은 현재 검증된 원문 전체를 대상으로 삼는다.
- 분할 검증이 참가자격 전체를 추가 완료 조건으로 요구했다. 서류별 주체·단계·기한·방법·대체 조건 및 선행 등록기한을 보존하되 업종·소재지 전체 설명을 요구하지 않는 공통 완료 기준을 추가했다.
- 조각에 정보가 없다는 문장을 전체 공고 정보 부재처럼 반복하지 않도록 생성·검증 지침을 일치시켰다.

마감일이나 서류명을 응답 코드에 하드코딩하지 않았다. 예산·누락·검증 실패는 계속 PARTIAL로 남는다.

## 실행 근거

- 오프라인 442 PASS: `.ci-results/copilot-v31-20260914T220814Z/tests.xml`.
- 첫 브라우저 검사 `browser-2026-09-14T22-01-53-650Z`: 문서 옵션을 켜지 않은 테스트 설정 오류. PARTIAL. 원래 실패 재현으로 인정하지 않는다.
- `browser-2026-09-14T22-03-21-539Z`: 문서 옵션 활성화. 마감·서류를 설명했으나 15부분 중 1부분의 검증 실패로 PARTIAL. 범위 요구 및 부분 부재 반복 발견.
- `browser-2026-09-14T22-05-31-837Z`: 계획 모델이 저장 판정 조회로 분류해 PARTIAL.
- `browser-2026-09-14T22-07-29-642Z`: 문서 조회 고정 후에도 검색이 일반 발췌만 선택해 PARTIAL.
- 실제 브라우저 검사 스크립트: `scripts/check_local_document_deadlines.mjs`. HTTP200만으로 통과시키지 않고 processing PASS·마감일시·확인서·청렴 서류·actions0을 확인한다. 응답 mock 없음.
- 전용 평가 PostgreSQL 읽기 전용 확인: 답변1건, 연결 판정 `bbf456f8-6aaa-4825-af31-3c79aa008ab8` 유지.
- 최종 실행 `browser-2026-09-14T22-08-51-242Z`: **PARTIAL / 테스트 FAIL**. 원문 65부분 중 EXPLAINED25, OUT_OF_SCOPE37, NEEDS_REVIEW3. 실제 모델 호출30개 성공. 마감일과 주요 서류를 본문에 포함했으나 u71은 다른 부분의 시점 확인 안내, u78은 고철 서류 제출시점 오설명, u80은 현장 확인서 제출 의무 누락으로 통과하지 못했다. 검증 실패 원문을 별도로 남겼으며 PASS 기준을 낮추지 않았다.
- 모델 예산 예약 추정 누계는 이번 시작 $0.3536 → 종료 $0.7412. 증가 $0.3876은 여러 진단 실행 합계이며, 마지막 실행 증가는 $0.2312로 실행당 $0.25 이내다. 제공자 실청구 금액이 아니다.
- 현재 로컬 API에는 수정 적용됨(`api-v11.log`). 원래 사용자 실패와 최종 실패 로그 모두 보존. 원격에 올리는 것은 코드·검사 스크립트·이 보고서이며 원문 사본/계정/응답 원본은 제외한다.

원문·브라우저 응답 전체·계정 파일은 Git에 추가하지 않는다. 이번에는 DB 스키마/저장 로직을 변경하지 않았고 DB/API 전체 검사는 재실행하지 않았다. 이전 60 PASS를 이번 실행으로 합산하지 않는다.

## Q-011 — 장문 검토 결과를 서류별 답변으로 합치는 단계

**근거:** 원문 분할 검토는 입력 누락을 막았지만 최종 응답은 부분별 문장을 이어 붙인다. 동일 서류가 중복되고 청렴 서약 상세가 길게 나오며, 단계·기한의 부분별 불일치를 사용자에게 넘긴다. 최종 실모델 실행도 3부분 미검증 상태다. Q-007에서 해결한 특정 질문의 완료 범위만으로 일반 서류·기한 답변이 해결됐다고 볼 수 없다.

**대안 A:** 입력 한도나 재시도 횟수만 늘린다. 비용/지연이 늘고 중복·단계 충돌은 남는다.

**대안 B:** 검색 상위 발췌만 사용한다. 빠르지만 이번과 같은 본문 누락이 재발한다.

**권장안 C:** 원문 span별로 서류명·제출 주체·단계·기한·방법·대체 조건을 추출하고 각각 출처를 유지한다. 검증된 레코드를 서류별로 합친 뒤 중복 제거와 기한 충돌 검사를 한다. 사용자에게 입찰/현장/계약/이행 단계별 간결한 표를 제공하고 미확정 필드는 해당 서류에 붙인다. 병합된 결과도 원문 참조와 독립 대조하며, 미검증 항목을 삭제해 완료로 바꾸지 않는다.

**설계 대화 전달 질문:** 서류·마감일 답변을 위 레코드 및 단계별 표 형태로 통합하고, 미확정 기한은 해당 서류에 표시하는 방향에 동의하는가? 계약 후 이행 서류를 기본 응답에 함께 포함할지 별도 구획으로 둘지 확정해 달라. 이 제안은 아직 구현하지 않았다.

## 남은 작업

① 감사 → ② 연결 → ③ 기본 검사 이후 ④ 통합 검증 보완 / ⑤ 사용자 평가 중이다. ⑥ 최종 통합 판단은 미진행. Q-009 해석, Q-010 정정 설계, 저장 근거 JSON 표시, 다양한 질문과 최신 develop 비교가 남는다. 이 한 질문의 결과를 범용 공고 QA 완료로 확대하지 않는다.
