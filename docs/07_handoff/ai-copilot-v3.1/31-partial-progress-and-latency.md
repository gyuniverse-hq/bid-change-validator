## Q-015: 일부 실패가 전체 재생성과 긴 응답을 반복시키는 구조

- 근거: 기존 `finish_turn`은 전체 turn의 complete가 false이면 모든 요청을 OPEN으로 남겼다. 문서 chunk 검토 캐시는 있었지만 큰 문맥 경로의 검증된 설명·완료 기준을 후속 생성에 재사용하지 않았다. 두 사용자 요청 모두 plan → generate → validate → repair → revalidate 5회 순차 호출을 했다. 예약 시각 기준 첫 plan부터 마지막 revalidate 시작까지 각각 66.18초·72.70초였다. 당시 로그에 종료 시각이 없어 전체 응답 시간은 확정할 수 없다.
- 대안: (A) 검증 생략 또는 제한 완화는 잘못된 답변을 완료로 만들 위험이 있다. (B) 화면만 짧게 줄여도 생성·재검증 반복은 남는다. (C) 현재 근거를 다시 읽고 동일성 확인 후 독립 검증된 문장·완료 기준을 재사용하며, 미완료 항목만 생성·검증한다.
- 권장·반영: C. 일부 항목 실패를 숨기지 않으면서 완료된 설명과 남은 항목을 분리했다. 긴 문서에서는 자동 repair/revalidate 대신 한 번의 생성·검증 결과를 반환하고 사용자 후속 요청에서 남은 범위를 다룬다. 짧은 요청·저장 제안의 기존 검증/실행 경계는 유지한다.

## 변경 내용

1. 대화별 한 개의 제한된 answer_review에 검증된 semantic 주장과 서버가 평가한 완료 기준을 보존한다. 원문 인용 fallback·미검증 주장은 완료 증거로 재사용하지 않는다. 원래 목표, 완료 기준, scope, 실제 다시 읽은 facts/sources, fingerprint, coverage, 서버 판정 문맥 전체의 해시가 동일해야 재사용한다.
2. 후속 요청에서도 원문·제품 자료를 다시 읽어 최신성을 확인한다. 비싼 생성·검증은 남은 완료 기준의 근거로 좁힌다. 유지한 주장 ID와 새 주장 ID를 분리하고, 이전 MET와 새 검증 결과를 실제 SUPPORTED 주장 연결로 다시 합산한다. 참조 존재나 모델 MET만으로 완료하지 않는다.
3. READ_CHECKS의 개별 기준이 검증되면 다른 작업 실패와 분리해 완료 상태를 보존한다. 문서의 서류와 일정 기준을 분리한다. 전체 요청 기준 GOAL은 별도로 유지한다. 가정·제안은 실제 실행으로 승격하지 않는다.
4. 응답에는 새 설명만 표시한다. 남은 기준과 처리 내역을 보여주고 원문 fallback, 문장별 근거 목록, 항목별 추가 확인 목록은 펼쳐 볼 수 있게 접는다. 원문과 근거 링크 자체는 삭제하지 않는다.
5. 로컬 모델 예산 장부에 호출별 실제 elapsed_ms·usage를 추가 기록한다. 기존 예약액을 초기화하지 않는다.
