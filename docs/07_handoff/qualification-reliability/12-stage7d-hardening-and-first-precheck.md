## 1. 7-D1 — 금액 역할·단위 검증

legacy/review_v1이 공유하는 슬롯 정규화와 canonical mapper를 수정했다.
금액 슬롯은 범용 숫자 파서 대신 원화 전용 파서를 사용하고, 교체 normalizer와 직접
canonical 호출에서도 KRW/숫자/연산자/원문 값을 확인한다. 기간·인원·식수 결과를 금액으로
허용하지 않는다. `1일 평균 800식 이상 → 0.0333 MONTH → PERFORMANCE_AMOUNT` 경로를 차단했다.
잘못된 금액이 같은 실적 슬롯에 있으면 그 금액만 버리고 더 쉬운 나머지 조건만 확정하지 않는다.

1만원 하한은 도입하지 않았다. 실제로 명시된 1원·소수 금액과 명시적 상하한은 처리한다.
알 수 없는 조합/통화/분리된 여러 표현은 미해결이다. 명시 금액이 예산인지 실적인지 등 자연어
역할 판단까지 이 파서 하나가 보증하지 않는다. 세부값은 같은 원문 요건 범위에 연결되어야 한다.
원문의 부가세 표현은 유지하며 범용 파서·기존 판정 규칙·그래프 파서는 바꾸지 않았다.

## 2. 7-D2 — 중복과 업종/등록 이중분류

슬롯 canonicalizer 뒤에 좁은 중복 정리를 연결했다.

- 유형/연산자/값/단위/기간/scope/필수·선호/복합성/공고 차수가 다른 조건은 합치지 않는다.
- 같은 논리 그룹 또는 두 단일 ALL_OF 그룹의 동일 조건만 통합한다.
- `(A OR B) AND (A OR C)`의 두 A 연결을 삭제하지 않는다. 27개 진리값 조합 테스트.
- 단일 업종명과 단일 코드가 원문으로 연결되는 경우만 별칭을 정리한다.
- 같은 청크라는 이유만으로 별개 등록/허가를 합치지 않는다. ISO·직접생산확인 등은 보존한다.
- 입력 객체를 변경하지 않고 원래/보존 요건 key와 양쪽 근거를 진단에 기록한다.
- 통합 요건은 양쪽 근거를 모두 유지한다. 단순히 나머지 모든 요건 근거를 붙이지 않는다.
- 서로 다른 raw는 구조화되지 않은 제약이 있을 수 있어 기본적으로 통합하지 않는다.

단체급식업등록과 명시적 업종 1450의 이중분류 사례를 합성 회사 + 실제 판정기로 확인했다.
정상적인 미달을 충족으로 바꾸는 목적이 아니라 같은 사실의 잘못된 인증 미달을 방지한다.
그래프 경로의 deduplicate_atoms/원래 논리 계산은 변경하지 않았다.

## 3. 7-D3 — 절차와 자격 분리

나라장터/G2B 등록 절차를 일반 인증 이름으로 만들어 회사 인증 목록과 비교하지 않는다.
혼합 조항 전체를 LEGAL_PROCEDURAL_RULE로 버리는 #142 가드는 가져오지 않았다.
원문 속 실제 업종코드는 유지하고 절차는 `PROCEDURAL_REQUIREMENT_REVIEW` 경고와 근거로 남긴다.
절차를 분류했다는 것이 절차 이행/면제/무관함의 확인은 아니므로 NOT_CHECKED 상태다.
그 결과 PARTIAL/확인 필요가 생길 수 있다. 이 확인 비율을 자동 판정 개선 수치로 숨기지 않는다.
현재는 절차 사실·증빙 입력과 자동 이행 검증까지 추가한 것이 아니다.
공통 clause_safety 및 기존 판정 규칙 파일은 수정하지 않았다.

## 4. 7-D4 — legacy 위계·근거·탈락 진단

기존 제목 위계는 이미 있었으며 보존했다. 날짜를 새 제목으로 오인하지 않는 보완/회귀를 추가했다.
legacy 인용은 review_grounding을 사용해 실제 원문 구간으로 복원한다. 공백·장식기호 차이는
복원하지만 `12년 → 2년`, `1.3억원 → 3억원`, `14501 → 1450` 같은 숫자 부분 인용은 차단한다.
원문 요건의 범위 밖 사업예산을 실적금액으로 가져오거나, 떨어진 표현을 이어붙여 통과시키지 않는다.
여러 동일 구간 중 하나를 임의 선택하지 않는다. 이는 안전한 인용을 강화하지만 짧은 raw/청크를
넘는 실제 조건은 더 많이 보류할 수 있다. 여러 근거가 필요한 경우는 그래프 해석/근거 선택이 필요하다.

`dropped_requirements`에 detail_field/detail_value/validation_code를 선택적으로 저장한다.
없는 필드는 serializer에서 생략해 과거 raw/reason_code JSON 형태를 유지한다.
저장 POST/GET에서 상세 탈락 진단이 유지되는지 실제 PostgreSQL로 확인했다.
원문 복원 정책에 맞춰 기존 compatibility-dot 테스트의 raw 기대값을 실제 source로 변경했고
나머지 기존 테스트의 검증 대상은 유지했다.

실행 메타데이터에 `slot_pipeline_version=qualification-slot-pipeline-v2`를 기록한다.
이 기록만으로 오래된 결과를 마이그레이션하거나 옛 변경 비교의 모든 버전 선택 정책을 바꾼 것은 아니다.
기존 실행을 덮어쓰지 않으며 수정 전후 결과는 같은 원문이면 분석 기준 차이로 검토해야 한다.
