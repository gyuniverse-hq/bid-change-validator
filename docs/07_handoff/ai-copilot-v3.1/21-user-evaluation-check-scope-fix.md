## 실제 사용자 발견

질문은 “추가 답변이 필요한 확인 질문을 알려줘.”였다. 사용자 붙여넣기에서 현장 방문 질문의 저장된 근거에 운반 장비 주의 문구가 들어갔고, 운반 예외 질문에도 현장 방문 근거가 인용됐다. 저장 프로필로 이미 충족한 업종의 원문 검토 질문까지 함께 나왔다. 직접 확인 항목의 집계는 3건인데 링크는 4개였다. 이 결과를 사용자 평가 실패로 기록한다. 붙여넣기만으로 당시 모델 내부 PASS/PARTIAL 상태는 확인할 수 없다.

## 원인과 변경

1. 확인 계약이 있는 질문 모두에 운반 장비 주의 문구를 붙이던 함수를 수정했다. 계약별 실제 확인 필드를 안내하고, 법적 운반 자격 주의 문구는 WASTE_TRANSPORT에만 붙인다. 현장 방문 계약은 방문 완료와 확인서 제출을 묻는다.
2. 명시적으로 추가 답변 질문만 요청한 경우 서버가 READ_CHECKS만 계획하고, 현재 askable 질문만 전달한다. 전체 공고 검토를 함께 요청한 복합 질문은 이 제한 규칙에 넣지 않는다. 임의의 모든 자연어 표현을 지원한다고 주장하지 않는다.
3. 각 질문에 같은 requirement_key·동일 provenance의 실제 원문 근거를 연결한다. 서로 다른 확인 항목의 facts를 한 claim에 합치면 기계 검증이 MIXED_CHECK_ENTITIES로 거절한다. 모델에도 질문별 분리를 지시한다.
4. 광범위 조회의 수동 검토 진단은 근거 여러 개를 한 항목으로 묶는다. 추가 답변 질문이 없으면 그 사실을 안내하되 전체 참가요건 충족으로 단정하지 않고 가짜 후속 대상을 만들지 않는다.

판정 알고리즘·규칙 버전·Q-009 보류·회사 프로필·사용자 답변·공용 DB를 변경하지 않았다. 읽기 조회와 질문 작성·근거 검증을 보완했다. 미입력 인증의 기존 미달 판정은 별도 평가 대상이며 이번 수정으로 뒤집지 않았다.
