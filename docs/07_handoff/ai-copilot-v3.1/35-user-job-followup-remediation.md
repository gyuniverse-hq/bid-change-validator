# 사용자 job 평가 후속 보완 (2026-09-15)

## 상태

남원과 구내식당의 사용자 평가를 바탕으로 후속 요청 보존·표시·예산 오류를 보완했다. 전체 job 사용자 평가 완료나 Core 전체 통과를 의미하지 않는다.

## 확인한 원인과 변경

- 미완료 job 재개에서 같은 도구라는 이유로 새 task.question을 이전 request로 덮어쓰고, plan.goal도 이전 목표로 바꾸는 경로가 있었다. 현재 요청과 하위 질문은 유지하고 기존 미완료 항목·실행 기록만 별도로 보존한다. 이전 목표와 같은 캐시 키를 만들어 새 체크리스트 요청이 사라지는 경로를 제거했다.
- 검토 상세는 미완료일 때 자동 펼침이었다. 항상 기본 접힘으로 바꾸고 내부 검증 지시·모델용 하위 질문 대신 도구의 사용자용 이름과 처리 상태만 표시한다. 미검증 원문은 기존 기본 접힘을 유지한다.
- 검증된 본문이 하나도 없으면 원문만 나열하지 않고 답변을 완성하지 못했다는 안내를 표시한다. 완료 상태를 상향하지 않는다.
- 현장 방문 답변에 정확한 미리보기/저장 금지 문장이 붙는 경우 저장 없는 제안으로 해석한다. 최신 턴에 제시한 실제 질문, 현재 기준, 유일한 대상 확인은 유지한다. 임의 복합 문장과 실행 추가 명령은 허용하지 않는다.
- 사용자 평가에서 사용한 저장 답변 결과 질문을 저장 영수증 조회로 연결했다. 영수증이 없으면 없다고 답하며 공고 변경으로 대체하지 않는다.
- 생성·검증에 한국 날짜를 제공하고 지난 일정·제출 단계 구분을 생성 기준에 명시했다. 이 프롬프트 변경만으로 일정 정확도가 보장되지는 않는다.
- 모델 처리 한도 실패를 자료 부족과 구분해 표시하고 실패 코드도 보존한다.

## Q-016 — job의 검증된 의무·일정 유지와 체크리스트 분류

**근거:** 같은 J05 세 턴에서 앞서 읽은 가격입찰 마감이 최종 체크리스트에서는 ‘발췌에 없음’으로 바뀌었다. 공동수급·하도급 불허와 발표 참석자의 제출 의무를 참고·협조사항 아래 표시했다. 설명 검증은 해당 문장 일부를 SUPPORTED로 처리했다. 원문만 재출력하던 문제는 개선됐지만 업무 사실의 지속성과 분류 정확도는 미완료다.

**대안:** (A) 생성 문구만 더 지시하면 근거 범위가 달라질 때 동일 문제가 남는다. (B) job에 확인된 의무/대상/기한/방법/예외를 출처·버전과 함께 유지하고, 후속 요청 때 현재 근거 일치를 확인하여 재사용한다. 미확인이나 충돌한 정보는 별도 상태로 유지한다.

**권장:** B. 의미 없는 원문 요약 캐시나 통과 문장 수를 완료 기준으로 쓰지 않는다. 체크리스트의 ‘필수/협조/선정 후’ 분류도 검증 대상에 포함하고, 이전에 확인한 사실이 누락되거나 확인 불가로 후퇴하면 이유를 표시한다. MIXED_CHECK_ENTITIES 경계를 풀어서 통과시키지 않는다. 기존 검증된 사실 유지 방식과 완료 기준을 함께 보완한 뒤 같은 job으로 재검증한다.
