## 현재까지 연결된 것

1. 원문 블록/차수/출처 기반 candidate ID와 처리 누락 검사.
2. 상위 조항·각주·참조 힌트, 요청 분할, 실제 요청 범위와 SHA-256.
3. `review_v1`의 후보별 추출 호출·응답 검증·미응답만의 제한 재요청.
4. **이번 변경:** 그 실행기에서 exact 또는 비교용 정규화로 유일한 원문 인용을 복원.
5. 모델이 공백/장식기호를 다르게 쓴 경우도 저장값과 위치는 실제 원문에서 획득.
6. 다른 후보/문서 참조 차단과 기존 문맥 의존·미해결 보류 정책은 유지.

## 구현됐지만 아직 모델/제품 경로에 연결하지 않은 것

- `review_operands.py`: 원문 수치의 역할별 정규화. 역할·기준일 선택은 호출자 책임.
- `review_conditions.py`: 원자 조건의 의미 지문, 중첩 논리 그래프 검증/계산, 그룹을
  보존하는 원자 중복 통합, 같은 실적에 모든 조건을 적용한 뒤 건수를 계산하는 함수.
- 모델이 역할/그래프/면제 적용을 맞게 선택하는지는 미검증이며 기존 판단을 대체하지 않는다.
- 기존 slots 응답은 조건 트리를 반환하지 않는다. 이것을 새 그래프에 임의로 끼워 맞추지 않았다.

## 이번 실행 검증

Python 3.13.5 / pytest에서 **246개 통과**:

- 기존 `test_review_execution.py`: 53개 재실행
- 신규 `test_review_source_semantics.py`: 70개
- 신규 `test_review_condition_logic.py`: 123개

하위 subtest 22개는 별도 테스트 수에 중복 합산하지 않는다. 기존 1~2단계 70개와
3단계 provider/분기 12개를 이번 실행 수에 합산하지 않는다.
실제 후보/계획/실행/슬롯 변환 모듈을 사용했고 모델 callable만 대역으로 교체했다.
새 논리 모듈의 입력은 합성 구조/판정값이며 실제 모델의 해석 정확도를 측정하지 않는다.

기존 입력 모듈과 재실행 테스트는 GitHub blob SHA가 일치하는 파일로 가져왔다.
새 변경 파일은 구문 컴파일 통과. 전체 API 회귀/실제 DB·LLM/J14·구내식당 반복/
실제 기존 판정기·브라우저·Copilot E2E는 이번에 실행하지 않았다.
