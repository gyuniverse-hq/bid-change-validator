## 4-B에서 연결한 것

- 재시도/시간/호출 예산을 가진 기존 실행기에 선택적 응답 계약을 주입한다.
- 기본 슬롯 응답을 바꾸지 않고 별도 의미 그래프 응답을 받는다.
- 값/기간/금액/비교연산자는 근거 구간에서 코드가 읽는다. 모델은 원문과 역할을 선택한다.
- 값/수식어는 해당 원자조건의 원문 구간 내부에서 확인한다.
- AND/OR/NOT/명시적 면제의 참조·범위·표식을 확인하고 중첩 그래프를 유지한다.
- 모델링되지 않은 일부 명시적 코드/인증/수치와 미해결 문맥을 진단한다.
- 그래프의 원자들을 **실제 기존 judge_requirement와 CompanyProfileSnapshot**으로 판정한다.
- 원자 판정 결과를 원래 그래프에 적용한다. 중복 원자를 공유해도 각 그룹의 연결은 남긴다.
- PERFORMANCE_COUNT에서 같은 실적의 기간·분야·운영개월·일일급식량을 함께 검사한다.
- 부가세 기준이나 기준일 자료가 없으면 추정값을 넣지 않는다.
- 회사 자료 오류는 모델을 호출하기 전에 검사한다. 모델 입력에는 회사 프로필을 보내지 않는다.

## 이번 검증

`test_review_semantics.py` 36개 + `test_review_semantic_judgment.py` 57개 = **93개 통과**.
실제 원문 후보/계획/실행/복원/피연산자/조건/새 컴파일러/새 연결 코드와
기존 contracts/judgment/clause_safety/extensions/normalization을 사용했다.
모델 네트워크만 대역이며 기존 판정 함수의 반환값은 모킹하지 않았다.

테스트 로더는 앱 패키지 초기화의 SDK/DB 부수효과를 제외하기 위해 임시 패키지 경로를
등록한다. 실제 모듈 파일은 그대로 로드한다. 전체 FastAPI 부팅/DB 테스트는 아니다.
검증용 기존 파일은 GitHub blob SHA와 일치 확인했고 변경 파일은 구문 컴파일 통과했다.
다른 단계의 테스트 수나 동일 테스트의 반복 실행 횟수를 이번 수에 합산하지 않는다.

## 아직 남은 한계

- 자연어 해석의 참/거짓을 코드가 완전히 증명하는 것은 아니다. 원문 구간 일치,
  관계 표식, 일부 명시적 값 누락 검사만으로 모든 의미 오류를 잡을 수 없다.
- 다중 조항 적용/다른 문서 참조/대표사·공동수급 주체는 pending으로 보존한다.
- 운영기간·급식량의 추가 사실은 Backend가 제공하는 별도 RecordObservation이다.
  현재 DB/화면의 입력 필드를 추가하지 않았으며 없는 자료를 만들어 채우지 않는다.
- 일부 필터/금액 조합은 명시적으로 미지원 UNKNOWN으로 남는다.
- 출력은 **조항별 조건 판정**이다. 전체 공고 결과를 임의 ALL_OF로 만들지 않는다.
  `notice_overall_status`는 None이며 다음 상태/적용 범위 계약에서 다룬다.
- 새 경로는 현재 제품 HTTP API에서 기본 실행되지 않는다.
- 실제 LLM/J14·구내식당 반복/전체 API/DB/브라우저/Copilot/변경공고 E2E는 미실행.
- 93개 통과는 모델 성능 향상, 신규 공고 일반화, CI 전체 통과의 증거가 아니다.
