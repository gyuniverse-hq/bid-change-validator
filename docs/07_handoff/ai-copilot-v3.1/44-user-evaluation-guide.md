## 순서

전체 작업은 ① 감사 → ② 서비스 연결 → ③ 기본 검사 → ④ 통합 검증 → **⑤ 아래 사용자 평가** → ⑥ 최종 통합 판단이다.

1. `http://127.0.0.1:5181/login`을 연다. 계정과 비밀번호는 같은 실행 폴더의 `accounts.private.json`에서 해당 label을 찾는다. 이 파일은 로컬 전용이며 Git에 올리지 않는다.
2. 로그인 후 회사 프로필의 업종과 소재지를 아래 표와 비교한다. 모든 입력은 합성 자료다. 증빙 보유를 선택한 경우에도 실물 검증을 뜻하지 않는다.
3. 아래 회사의 링크를 열고 AI Copilot에서 **한 Job의 질문을 같은 대화에서 차례로** 보낸다. 공고문 근거 답변을 켜고 평가한다.
4. 답변의 정확성, 빠진 요청, 반복/길이, 응답 시간을 기록한다. “요청 처리 완료”는 설명·절차 안내 상태이며 현실의 모든 참가자격이나 제출 완료를 뜻하지 않는다.
5. 다른 회사로 갈 때 로그아웃 후 해당 계정으로 로그인한다. 이전 회사의 탭·대화를 그대로 사용하지 않는다.

준비된 원문·분석·판정을 평가하므로 **다시 검토/전체 재분석을 누르는 것은 이 순서에 포함하지 않는다.** 최신 전체 추출 경로의 설정과 비용은 이 평가 API와 구별된다. 브라우저 새로고침 또는 API 재시작으로 대화가 초기화될 수 있지만 저장된 판정·추가답변은 DB에 남는다.

**C1 구내식당**

1. “우리 회사가 이 공고에 참여하려고 해. 현재 회사 정보로 충족하는 조건과 추가로 확인할 사항을 정리하고, 제출할 서류와 각각의 마감일·제출 방법까지 확인해서 준비 순서를 알려줘. 근거가 부족한 부분은 따로 표시해줘.”
2. “처음 부탁한 참여 준비에서 아직 확인하지 못한 항목이 정확히 뭐야? 확인할 수 있는 것은 이어서 확인하고, 끝내 확인할 수 없는 것은 이유와 내가 해야 할 행동을 알려줘. 이미 설명한 내용은 반복하지 마.”
3. “지금까지 내용을 바탕으로 내가 실행할 체크리스트를 만들어줘. 필수 제출과 참고·협조사항을 구분하고, 마감일이 지난 일정은 따로 표시해줘.”

14시 전자투찰과 15시 방문접수, 설명회 참석서류, 발표 증빙의 최근 3개월 조건, 입찰보증금과 보증기간, 안전보건관리 이행 서약서의 등록 단계·계약 단계가 각각 남는지, 선정 후 안전보건관리계획서와 구분되는지 본다. 같은 항목이 여러 번 보이거나 답변이 길면 정확성과 별도로 기록한다.

**C2 우치공원**

1. “기준 공고에서 현재 공고로 바뀌면서 삭제된 자격 요건과 남아 있는 요건을 구분하고, 회사에 미치는 영향과 대응할 일을 설명해줘.”
2. “삭제된 요건은 우리 회사가 충족한 것으로 바뀐 거야?”
3. “현재 공고에서 아직 확인할 자격 조건과 그 원문 근거만 정리해줘.”

삭제는 회사가 그 요건을 충족했다는 뜻이 아니다. 문서에서 찾은 조건과 실제 개별 저장 판정도 구별되어야 한다.

**C3 한림대**

1. “기준과 현재 공고에서 달라진 메타데이터와 실제 자격 조건을 구분하고, 회사 판정이 바뀌는지 설명해줘.”
2. “표시가 달라졌다는 이유만으로 참가 가능 여부도 달라졌다고 볼 수 있어?”
3. “그 판단의 근거와 내가 추가 확인할 일만 정리해줘.”

업종 제한 N→Y 표시만으로 실제 자격 변경이나 참가 가능→불가를 단정하면 오류다. 전후 판정 연결이 없으면 비교 불가 사유를 설명해야 한다.
