# 사용자 평가 준비표 — 아직 평가 시작 전

현재 단계는 **4 통합 검증**이다. 전체 순서는 1 감사 → 2 구현·연결 → 3 기본 검사 → **4 통합 검증** → 5 사용자 평가 → 6 최종 통합 판단이다.

18번은 이전 보완 기록이며, 최신 결과는 [19번 완료 범위·원문 대조 보고서](19-completion-scope-and-q009-review.md)다. Q-007 참가자격/작성·제출 두 장문 요청은 실모델 검사를 통과했다. Q-009는 공식 화면과 첨부 공고문 간 불일치가 확인되어 기관 해석 확인을 기다린다. 평가 전에는 업종군 관계와 합성 프로필 보충값을 검수하고 고정 평가 환경을 준비한다. 자동 검사 통과를 사람의 이해도·자유 질문 성공으로 대신하지 않는다. 현재 사람 평가 결과는 모두 NOT_RUN이다.

## 평가 환경

- 후보 코드: `codex/ai-copilot-evaluation-ready`, 별도 worktree `.ci-results/evaluation-ready`.
- 공용 DB의 자료를 변경하는 평가를 하지 않는다. 전용 로컬 PostgreSQL에 출처가 고정된 자료와 검수한 합성 프로필을 적재한다.
- 현재 테스트 runner의 계정은 실행 후 정리된다. 고정 사용자 평가 계정은 아직 배포/공유하지 않았다.
- 일반 개발 경로는 의미 처리 OFF 기본값을 확인하고, 실모델 평가를 할 때 사용자가 의미 처리와 공고문 처리 동의를 각각 켠다.
- 남원 자료는 저장 DB snapshot의 별도 재추출본이다. v1/v2 HWP·PDF 원본 byte hash와 PDF 참가자격 페이지의 시각 대조를 확인했다. 이는 전체 문서의 독립 사람 검수나 발주기관의 법적 해석 확정이 아니다. 이 자료는 000→001 과거 변경 사례이며 최종 공고가 아니다.
- 세션마다 코드 commit, snapshot/fixture hash, 회사 프로필, 기준·현재 분석/판정 ID, 규칙 버전, 모델, 동의 상태를 기록한다.

## 과업과 확인할 결과

| 번호 | 사용자가 수행할 과업 | 평가 기준 | 현재 개발 검증 |
|---|---|---|---|
| U01 | 로그인하고 회사·공고를 선택 | 다른 회사 자료가 섞이지 않음 | 실제 브라우저 통과 |
| U02 | “추가 답변이 필요한 확인 질문을 알려줘” | 질문 목록 요청을 증빙 제출 완료 과업으로 확대하지 않음 | 합성 실모델/화면 통과 |
| U03 | “판정에 사용한 회사정보만 요약해줘” | 요청한 profile snapshot 설명, 미입력과 미보유 구분 | 합성 실모델/화면 통과 |
| U04 | “두 번째 요건” → “그 요건” → “우리 회사와 비교” | 동일 요건 유지, 비교에 실제 회사 근거 사용 | 실제 API/DB/모델 통과 |
| U05 | 같은 질문을 다른 표현으로 말하기 | 전체 검토 범위가 planner 표현 때문에 줄지 않음 | 합성 2표현 통과 |
| U06 | 남원 전체 참가조건·예외·현장 방문 설명 및 별도 작성·제출 요청 | 요청별 완료 범위 일치, 조건·예외 누락 없음, 읽지 않은 범위를 완료로 표시하지 않음 | 19번 두 요청 실모델 PASS. 반복·길이의 읽기 편의성 평가와 Q-009 해석 확인은 남음 |
| U07 | 남원 J13~J16 프로필로 운반 조건 비교 | 코드 보유·법적 예외·미확인을 구분 | 4개 개별 운반 조건 재검증 PASS. J14/J15 세부 입력은 합성 보충값이며 검수 필요 |
| U08 | v1→v2 변경과 기존 참가 불가 이유 질문 | 원문/구조화 변경 구분, 전체 결과 반전 허위 설명 없음 | snapshot diff 재현, 실제 정답 검수 필요 |
| U09 | “등록을 보유했다고 가정” → “반영해줘” → “응” | 가정/제안은 미저장, 명시 확인 전 실제 변경 없음 | 합성 실모델·DB 통과 |
| U10 | 이전 규칙 결과 다시 판정 후 변경 재검증 | 기준·현재 판정 갱신, 중복 실행 없음 | 실제 브라우저·DB 통과 |
| U11 | 로그아웃 후 다른 회사 계정으로 재로그인 | 대화·선택·동의 초기화, 이전 회사 접근 차단 | 실제 브라우저·DB 통과 |
| U12 | 사전 제시하지 않은 자유 질문 | 사용자 목적 달성, 근거 설명 가능, 모호할 때만 확인 질문 | **NOT_RUN** |

정답표와 개발용 질문을 미리 본 사람이 독립 평가자라고 주장하지 않는다. 평가자는 답변의 어색함뿐 아니라 목적 달성, 조건/예외 누락, 잘못된 확정, 근거 접근, 추가 질문 횟수를 기록한다.

판정 반전을 보여주려면 다른 요건을 충족시키고 업종 조건만 바뀌는 별도 통제 프로필과 전후 기대값을 검수한다. 서울 소재 회사의 기존 지역 미달을 업종 변경 때문에 생긴 결과로 설명하지 않는다.

평가 진입 판단에는 19번 수정·재검증 근거와 **Q-009의 보류 범위, 검수된 프로필 및 평가 환경**이 필요하다. 사람 평가·통합 판단·배포를 완료했다고 기록하지 않는다.
